# Upgrade to Umbraco 19

From `18.0.0` (backoffice `18.0.0`, `[18.0.0, 19.0.0)` range) to `19.0.0-beta1` (tag `release-19.0.0-beta1`).
Branch `v7/dev`, cut from `origin/v6/dev` (package `6.3.0-alpha`). Worktree: `../BlockPreview-v7`.

**Targets CMS release:** `release-19.0.0-beta1`. The package ships as `7.0.0-beta1` (pre-release) until the final 19.0.0.

Status: **plan approved 2026-11-10. Inventory is partial** (see "Still to verify").

## Inventory

- **.NET 10 → .NET 11 (`net11.0`), SDK `11.0.100-rc.3.26522.148`, runtime async on** (beta1)\
  Source: `release-19.0.0-beta1:Directory.Build.props`, `global.json`; docs "Install .NET 11"\
  Hits: `Directory.Build.props`, `global.json` (SDK 10.0.200 pin), every project, CI (`.github/workflows/*.yml` SDK version)
- **Minimum upgrade source** is 16.4+; 18 → 19 is allowed. (docs "Upgrade from Umbraco 16.4 or later")
- **Block layout items get their own `Key`, separate from `ContentKey`; `IBlockLayoutItem` gains `Key`, `IsExternalContent`, `GetContainedLayouts()`** (beta1)\
  Source: umbraco/Umbraco-CMS#22448; `IBlockLayoutItem.cs`; docs "Reusable content in block editors"\
  Hits: `BlockPreviewService.cs:595,607,708-722` match layout items by `ContentKey`, which is no longer unique when the same Library element is used twice. Any layout/item lookup must use `Key`. Also `BlockDataConverter`, `BlockPreviewApiController`.
- **Reusable (Library) elements in Block List, Grid, Single Block and RTE** (beta1)\
  Source: #22448, #23195; `BlockEditorValues.cs` (a block value may now have layouts but no local content/settings data)\
  Hits: BlockPreview resolves content/settings from the block's own `ContentData`/`SettingsData` (`BlockPreviewService.cs:212,220,323,331,401,409,464,469,714,720`). External content blocks won't be found there. New behaviour to design: render external elements (preview them via the element service), or skip them.
- **`BlockEditorConverter.ConvertToElement(owner, data, cacheLevel, preview)` removed; only the overload with `owningPropertyCulture` remains. Element build now takes the `owner`** (beta1)\
  Source: #24015 (obsolete removal), `BlockEditorConverter.cs`\
  Hits: `Services/BlockDataConverter.cs` (wraps `BlockEditorConverter`). Check at compile.
- **`BlockItemVariation` loses `Segment` (ctor now `(key, culture)`); blocks exposed per culture only** (beta1)\
  Source: #23060; docs "Segment removed from content variant models"\
  Hits: none found by grep in `src/`; check at compile and in tests.
- **`BlockValue.SupportsBlockLayoutAlias` no longer obsolete; `JsonBlockValueConverter` prefers the editor's own layout alias** (beta1)\
  Source: #24015. Hits: `BlockDataConverter.cs:76` constructs `JsonBlockValueConverter`. Behaviour check only.
- **`IPublishedElement.OwningContentId` added** (beta1)\
  Source: #22448, #23753. Hits: none (the package has no `IPublishedElement` implementations); check at compile.
- **Default interface members removed (`IDocumentCacheService.GetByKeysAsync`/`TryGetCached`, `IEntityService.GetAll(objectTypes, …)`)** (beta1)\
  Source: #24015. Hits: `BlockPreviewApiController` consumes `IDocumentCacheService` and `IEntityService` (consumers are fine; only implementers break). Test mocks (`tests/…/Tests`) that implement these may need the new members.
- **Property value converters shadowed rather than removed; Block List single block mode removed; `ValidationLimit` is now `NumberRange`** (beta1)\
  Source: #23849, #23853, #23470. Hits: check `BlockPreviewService` / `BlockTypeCacheService` for reads of block config (`minAllowed`/`maxAllowed`).
- **Auth: backoffice moves to cookie-based authentication; `umb-app-oauth` removed; access tokens in extensions change** (beta1)\
  Source: #23484, #23616, #23698; docs "Cookie-based authentication", "Update backoffice extensions that use access tokens"\
  Hits: frontend imports `UMB_AUTH_CONTEXT` from `@umbraco-cms/backoffice/auth` (token for API calls) and the Management API controller's auth. Re-check `BlockPreviewApiController` auth attributes and client API calls.
- **Frontend type error against `@umbraco-cms/backoffice@19.0.0-beta1`** (beta1)\
  Source: `tsc --noEmit` in a scratch copy, peers set to the 19 beta1 versions\
  Hits: `src/blockEditor/block-grid-preview.custom-view.element.ts:208`: `UmbBlockGridLayoutModel` now requires `key`. Docs: `UmbBlockLayoutBaseModel` requires `key`; block-manager delete methods take a layout key.
- **Frontend peers moved** (beta1): `lit ^3.3.1`, `@umbraco-ui/uui ^2.1.1`, `@hey-api/openapi-ts >=0.99 <1.0` (package has `0.97.1`), `rxjs ^7.8.2`, `uuid ^14`, etc.\
  Source: `npm view @umbraco-cms/backoffice@19.0.0-beta1 peerDependencies`. Hits: `package.json`, `package-lock.json`, `openapi-ts.config.ts` (regenerate the client, `src/api`).
- **Package's own `[Obsolete(… "Scheduled for removal in v7")]` code** (inventory step 9, see Tasks): 18 members across `Constants.cs`, `BlockPreviewOptions.cs`, `DataTypeSavedNotificationHandler`, `BlockPreviewApiController` (3 ctors/actions + 3 stylesheet actions), `BlockViewRenderer`, `BlockPreviewViewResolver`, `BlockPreviewService`, `IBlockPreviewService`. Generated client `sdk.gen.ts` has 3 `@deprecated` operations (the matching endpoints).

## Breaking changes for consumers

Task 1 removed the package's own `[Obsolete(... "Scheduled for removal in v7.")]` members (public API; `PackageValidation` CP0002 against baseline 6.0.0 lists them). More may follow from CMS-forced signature changes found at compile.

- `BlockTypeSettings.Stylesheet` (use `Stylesheets`); the `"Stylesheet"` appsettings key no longer binds.
- `Constants.CacheKeys.BlockType`.
- `BlockPreviewApiController`: both obsolete constructors (without `IEntityService`; without `IBlockPreviewResponseEnricher`), and the actions `GetGridStylesheet`, `GetListStylesheet`, `GetRteStylesheet` (endpoints `GET preview/{grid|list|rte}/stylesheet`; use the `.../stylesheets` endpoints).
- `BlockPreviewService`: both obsolete constructors (the 19-parameter and the `ITypeFinder` one), `RenderRichTextBlock(blockData, content, controllerContext, blockEditorAlias, documentTypeUnique)`, `GetStylesheetPath(...)` and the protected virtual `CreateViewData(...)` (override `CreateViewDataAsync`, which no longer calls it).
- `IBlockPreviewService`: `RenderRichTextBlock(..., blockEditorAlias, documentTypeUnique)` and `GetStylesheetPath(...)` removed. The default implementations of the 3-argument `RenderRichTextBlock` and `GetStylesheetPaths` went with them, so they are now abstract: external implementers must implement both.
- `BlockViewRenderer`: constructor without `IServiceScopeFactory`/`ILogger`.
- `BlockPreviewViewResolver`: constructor taking `IWebHostEnvironment`.
- `DataTypeSavedNotificationHandler(AppCaches)` and `ContentTypeSavedNotificationHandler(AppCaches)` constructors.
- Generated client: `BlockPreviewService.getGridStylesheet/getListStylesheet/getRteStylesheet` and their types; `stylesheet` field on `BlockTypeSettings`.
